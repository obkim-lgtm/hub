화두 1

왜 데이터였나: 역량과 3년의 성장을 보고 싶다

처음의 요청 2021.11 – 2022.06

  • 그린스마트 미래학교 선정 후, 학교 비전(창의인·의사소통인 등)을 정량으로 보여줄 방법 필요
  • 교육 효과를 보여줄 데이터가 필요하나 학교 안에서는 쌓고 쓰기 어려움: 도구가 없거나, 있어도 교사가 쓰기 어렵다
  • 학생부에는 글로 된 기록만 남음 → 역량별 수치화, 3년 연속 관리, 학부모에게 역량 변화 전달 희망
  • 한 학년이 3년 동안 문제해결력이 어떻게 변했는지를 기록으로 확인하고 싶음. 모든 교사가 함께 써야 한다는 인식도 이때부터

논의 전개

  • 2022.03 AI 문장 생성·역량 분석 시연 후 학교에서 바로 활용해봐도 좋겠다 → 학년별 시범학급 3개 합의
  • 2022.06 정량 분석 결과는 볼 수 없나 → 정확한 점수 입력이 전제인데, 그러면 선생님 부담이 커지는 딜레마 확인
  • 2022.08 한 학생의 3년 데이터를 한 번에 볼 수 있다면 3학년 진로·진학 상담에 유효

현재 도달점

  • 학기별 리포트로 기록이 쌓이는 구조는 마련됨 (화두 5)
  • 2026.09 3년간 변화 추이가 나왔으면이 다시 요청됨 → 출발점의 질문이 여전히 다음 과제
화두 2

기록의 부담: 선생님은 클릭만 하면 되게

처음의 요청 2022.06 – 2022.07

  • 글을 직접 다 써야 한다면 나이스와 이중 작업이라 쓰지 않을 것: 빈칸으로 둘 확률이 높다
  • 수업 준비 기간(12~2월, 7~8월)에 미리 세팅하고, 학기 중에는 휴대폰으로 틈틈이 클릭해 체크
  • 실제 고충: 수행평가 점수를 교사마다 엑셀로 계산, 세특용 공통 문장 반복 입력 → 수행평가 점수 자동 계산만 되어도 가치

논의 전개

  • 2022.06 AI는 교과세특보다 행동특성(담임) 쪽이 맞지 않나 → 역량 점수를 차트로 보고 총평을 쓰는 방향으로 전환
  • 2022.07 흐름 합의: 성취기준 선택 → 상·중·하 평가 → 문장 생성 → 교사 수정
  • 2022.10 ‘기록 생성’ → ‘기록 샘플 생성’으로 이름을 바꿔 참고용이라는 위치를 분명히
  • 2022.12 시범운영 후기: 세특 쓰는 시간이 1/3로 줄었다, 예전에는 1시간에 3명, 지금은 10명, 학기말에 몰아서 쓰던 것을 그때그때 기록하게 됐다
  • 2023.05 반대 목소리도: 2·3학년은 한 반 10명 정도만 쓰던 세특을 모두 쓰게 되며 업무가 늘었다는 체감, 교내 의견 분분. 그럼에도 학생 한 명 한 명 기록의 차별점을 가져가겠다는 취지에는 공감

현재 도달점

  • 2025.07 새로 쓰면 30분, 수정하면 5분
  • 2026.05 초안의 90%는 유지하고 10% 정도 바꾼다, 다듬기 기능 만족도 높음
  • 추가 요청: 시도·학교마다 다른 생기부 기재요령(글자 수·기호)을 학교 단위로 한 번에 적용하는 기능
화두 3

AI 기록의 품질: 정확해야 하나, 다양해야 하나

처음의 요청 2022.06 – 2022.11

  • 30번 누르는 것보다 문장 30개가 한 번에 나왔으면
  • 생기부의 학생별 내용은 모두 달라야 한다
  • 시범운영 중 발견: 체크하지 않은 역량이 나오거나, ‘좋음’을 체크했는데 부족하다는 문장이 나오는 경우

논의 전개

  • 2022.12 생기부는 현재형으로, ~로 인해 자기관리역량이 향상됨 같은 마무리 문장 형식 제안
  • 2023.03 AI 모델 비교: 한쪽은 표현이 다양하나 방향이 어긋나고(‘하’ 평가인데 긍정 문장), 다른 쪽은 방향은 맞으나 문장이 다 비슷함 → 교과 관련은 정확도가 더 중요, 역량은 다양성도 필요
  • 2023.03 키워드가 있으면 ‘복사 붙여넣기’라는 오해를 줄일 수 있다, 지식 이해와 활동(수행 과정)은 구분해서 기록해야 한다
  • 2023.05 수학: 모두 만점인데 부정 표현이 많이 나오는 문제. 인문 교과는 잘 나오는 편
  • 2024.08 종합 기록에서 ~노력이 필요함 반복, 같은 뜻 문장 중복 → 지우는 데 더 오래 걸림
  • 2025.07 이 정도의 표현을 써줄 학생인가 → 점수대별 표현 사전 필요. 점수가 낮으면 ‘발전 가능성’으로 마무리
  • 2025.07 루브릭만으로 만든 기록은 학생 간 차이가 드러나기 어려움 → 과제물이 들어가면 학생마다 다른 기록이 나옴

현재 도달점

  • 학생 과제물의 실제 내용을 근거로 기록을 만드는 방향으로 자리 잡는 중
  • 2026.02 선생님마다 원하는 분량·방식이 다름 → 생성할 때 요청사항을 직접 입력하는 방식으로 보완하기로 함
화두 4

평가 설계와 루브릭: AI보다 먼저 세운 것

처음의 요청 2022.07 – 2022.09

  • 평가 요소는 성취기준과 교과핵심역량. 성취기준은 새로 짓지 않고 골라 넣되, 빈칸 하나는 남겨두기
  • 성취기준은 수업·평가의 나침반
  • 채점 단계는 3단계 고정이 아니라 3·4·5단계(수학은 5단계가 흔함), 한 과목은 대표 교사 1명이 설계
  • 배경: 방학 중 평가계획서를 만들고 개학 후 제출하면, 학기 중에는 바꾸기 어려운 학교 현실

논의 전개

  • 2022.11 설계를 완벽히 하지 않으면 넣기 꺼려진다 → 배점은 고정, 문구는 수정 가능하게
  • 2023.03 같은 교과 선생님끼리 설계 공유
  • 2023.11 총체적 평가를 분석적 평가로 바꾸는 지원, 첫 문장만 쓰면 나머지 수준 문장을 만들어 주는 기능 제안
  • 2024.04 루브릭 구성은 교사의 과제: 프로그램이 다 해주면 교사의 일이 사라지는 것처럼 보일 수 있다는 우려
  • 2024.08 안용중은 90% 이상 분석적 루브릭, 다른 학교는 아직 총체적 루브릭이 많음. 처음 루브릭을 설계할 때 클리포를 염두에 두면 기록이 잘 나온다, 채점요소 1개를 3~4줄로 자세히 쓰면 결과가 좋다
  • 2025.07 한문 수업의 노하우 공유 (화두 8)

현재 도달점

  • 현재는 채점기준을 AI가 함께 만들되, 선생님이 원하는 내용을 자유롭게 입력하는 방식
  • 2026.05 출제 의도를 반영하려면 모범답안과 채점 가이드가 필요하다는 결론. 2학기 또는 내년 1학기부터 쓸 수 있도록 곧 반영 예정
화두 5

평가를 학생·학부모에게 돌려주는 리포트

처음의 요청 2022.06 – 2022.11

  • 학생기록부가 글이 아니라 시각화되어 나갈 수 있으면 좋겠다. 이게 메인. 학년별로 쌓이면 교과별 발전 양상이 보임
  • 중학교 1학년은 학기마다 학부모에게 성장 리포트를 보내야 함 → 차트와 기록이 함께 가면 학부모의 신뢰
  • 2022.08 리포트가 나오지 않는다면 학생 평가 기능은 필요 없다. 엑셀로도 가능하다

논의 전개

  • 2022.10 아이들은 리포트를 자기 지표로 삼기 때문에 신중해야 한다 → 리포트는 정확성보다 소통 도구로 자주 쓰는 것이 목표
  • 2022.11 첫 리포트: 한 장짜리 통합본(역량 육각형, 프로젝트 점수의 평균 비교, 자주 쓴 단어) + 관심 과목은 눌러서 상세히. 진로 추천은 데이터가 부족해 제외
  • 목적은 두 가지: 학부모에게는 학교가 이런 관리를 한다는 신뢰, 선생님들에게는 다음 해 모두 참여할 분위기. 부족만 가득한 내용이면 받는 학부모의 마음을 고려해야 한다
  • 2023.01 첫 발송(카카오 알림톡). 2023.03 학부모들 반응이 좋았다
  • 2023 학생·학부모 설문: 내가 무엇이 부족한지 알게 됐다, 몰랐던 내 모습을 알 수 있었다 / 요청: 지난 학기와의 비교, 진로 조언, 한눈에 보는 요약, 어떻게 공부하면 좋을지
  • 2023.11 리포트의 핵심은 그래서 이 학생에게 무엇을 말해줄 것인가. 발송 과정 체계화 제안(교사 마감 → 관리자 승인 → 발송 → 열람 확인)
  • 2024 가입해야 보는 방식은 학부모 열람률이 낮음(약 10%) → 알림톡처럼 직접 받는 방식 필요

현재 도달점

  • 2026.05 세특·행발까지 다 들어가야 완성된 리포트
  • 2026.09 전 과목이 들어가며 방대해짐 → 핵심 요약(방사형 그래프), 3년 변화 추이 요청. 역량이 형식적으로 나오지 않고 학생의 실제 강점이 보여야 한다는 지적
  • → 한 장 요약 등 가독성을 높이고 리포트 전반을 개선할 예정
화두 6

역량을 어떻게 평가할 것인가

처음의 요청 2022.03 – 2022.10

  • 교육부 6대 역량과 교과 역량을 모두 확인·관리하고 싶음
  • 2022.10 6개를 기준으로 두고, 통합을 생각하면 최대한 6개에 맞춰 운용하는 것이 좋겠다
